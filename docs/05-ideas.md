## 2. Direction from the Slack discussion

Full thread: [`sources/slack/team-channel.md`](../sources/slack/team-channel.md)

**Ana Aguiar: an LLM as the interface to the home.** Her takeaway from MobiCom was that LLMs or agents will become the interface between humans and digital services, so an LLM interface to a connected home could be a good option. She asked what it would look like.

**Filipe: show it through one situation that combines several whiteboard ideas**, such as looking after the house while someone is away.

- "I'm away until Sunday. Keep the plants watered and reduce the heating while I'm gone." The agent checks the sensor readings, works out what needs doing, and adjusts the plan if the person comes home earlier.
- "Where did I leave my keys?" The agent checks recent observations and reports where they were last seen.
- It should recognise when something is not possible and explain why: "I can water the plants, but I can't reduce the heating because the thermostat isn't connected."
- At that stage there was no need to work out how detection works. Assume the sensors provide the last known location and focus on how the LLM uses it.

**Mushahid: use the interface to cut the effort of setting rules** for all devices. Rules set by voice command or generated by AI, then adapted in real time to the situation.

**Ana:** "We only need to write 2 pages. This already reads like a start."

## 4. First-pass fit with what we were given

This section is analysis added while filing, not a team decision. The Slack discussion happened before we had the kit, the MCP guide or the mentors' steer. Validate every row once the kit is online.

| Idea | What we have for it | Gap or risk |
|---|---|---|
| LLM interface to the home | The MCP server is exactly this: 16 tools an agent can call | Altice already demo this in their own guide, so on its own it will not surprise them |
| Rules by voice or generated by AI | Scenario tools: create, activate, run | "Adapted in real time" is logic we would build on top |
| Away-from-home caretaker | Scenarios, security arming (`AWAY`), device state and recommendations | Watering and heating need actuators that may not be in the kit, and extra devices cannot be added |
| Explaining what it cannot do | Device lists and capabilities tell the agent what exists | Works with any kit. A missing thermostat becomes part of the demo |
| Lost & found ("where are my keys?") | The camera feed plus a vision model | Nothing in the MCP gives object locations. The observation memory would be ours to build |
| Security systems | Three security tools, alarm history | Closest to what the platform already does |
| Elder assist, kid monitoring, pets | Camera and sensors | Privacy questions will come up in Q&A |
| HVAC automation | Depends on a thermostat or temperature sensor in the kit | Unknown until the kit is inventoried |
| Fridge inventory, recycling | Camera only | No dedicated hardware |

Two things from the kick-off bear on the choice:

- The mentors want to be surprised by a **useful use case** and said **not to underestimate the camera** ([02-challenge.md](02-challenge.md)).
- The organisers expect teams to say plainly **what is real and what is simulated** ([01-event.md](01-event.md)).
